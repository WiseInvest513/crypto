# Wise Crypto 人工策略发布台 V1 — 设计规范

日期：2026-09-06
状态：用户已授权进入实现；本轮为本地私有创作基础，不代表已接入生产 CMS 或 Wise ID。

## 核心任务

发布台只解决一个闭环：编辑者填写人工判断，提交给另一名复核者，复核通过后形成不可变的发布快照。普通用户和 VIP 只消费服务端脱敏后的内容，不接触草稿、来源链接或工作流记录。

## 页面与路由

- 私有入口：`/studio/strategies`。
- 不进入公开导航、sitemap、公开 Analytics 白名单或搜索索引。
- 桌面采用约 68 / 32 双栏：左侧连续编辑画布，右侧发布预览与检查。
- 手机采用单列：策略概况 → 关键价格区域 → 确认与失效 → 审核与风险 → 预览 → 检查；主要操作固定在底部。

## 信息架构

1. 工作流：草稿 → 待复核 → 已发布。
2. 策略概况：BTC / ETH、人工倾向、标题、摘要、适用周期、有效窗口。
3. 关键价格区域：角色、名称、下沿、上沿、依据、来源引用；最多八个。
4. 确认与失效：确认条件、失效条件和持续观察；各自有明确数量和长度上限。
5. 审核与风险：作者和复核者由服务端身份生成，来源与风险说明由编辑者填写。
6. 发布预览：只预览未来允许进入 VIP DTO 的字段；来源 URL、内部身份和审计记录不出现。
7. 发布检查：逐项显示真实完成状态；不通过时发布按钮不可用，服务端仍会再次验证。

## 可见文案锁

首屏只允许以下主文案：`Wise Crypto`、`人工策略发布台`、`草稿`、`待复核`、`已发布`、`策略概况`、`发布预览`、`发布检查`、`保存草稿`、`提交复核`、`发布策略`。登录或配置状态可使用对应的安全说明，但不加入营销文案、表现数据、胜率或示例策略。

## 视觉系统

- 画布 `#F5F5F7`，表面 `#FFFFFF`，主文字 `#1D1D1F`，次文字 `#6E6E73`，边线 `#E5E5EA`。
- 琥珀 `#9A6700 / #FFF8E6` 只表达人工层与待复核；主操作使用黑色；错误与撤回使用深红。
- 不使用绿色、渐变、霓虹、装饰指标或默认 Bento 卡片网格。
- 标题 32–40px，分区标题约 20px，正文与表单控件 16px，说明不低于 13px。
- 控件触控高度至少 44px；数字使用 tabular-nums。
- 容器以一个连续编辑面、细分隔线和一个右侧检查栏为主，不给每个字段另套卡片。

## 图标清单

- 信息：圆形 `i`，1.5px 线宽。
- 新增：加号，配合文字，不单独承担语义。
- 删除：线性垃圾桶，并提供可读标签。
- 展开：细线 chevron；手机预览与检查使用原生折叠语义。
- 状态：空心圆 / 实心琥珀点，同时保留文字，不单靠颜色。

## 核心状态与交互

- 草稿允许不完整；保存只做安全、结构与长度校验。
- 提交复核执行完整内容校验，待复核期间正文只读。
- 编辑者和复核者是独立 staff 角色，不能自审。
- 发布前要求显式确认；同资产有效窗口不得重叠。
- 发布快照不可原地编辑；撤回必须记录原因，失败时不回退或覆盖既有有效内容。
- 版本冲突禁止静默覆盖。
- 所有服务端动作再次鉴权，不把页面可见性当作安全边界。

## 当前存储与部署边界

- 本轮使用仅限本机的、Git 忽略的原子 JSON 存储，便于真实填写与流程验证。
- 部署生产环境默认关闭发布台；文件存储不冒充跨实例数据库。
- 未来接入 Wise staff 身份和私有 CMS / 数据库后，替换服务端适配器，不改变公开 `regular / vip` 合同。
- 当前不自动生成方向、价位、胜率、收益承诺或 Wise 判断。
