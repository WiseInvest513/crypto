# Wise Crypto VIP 行情研究基础

> 状态：首个基础批次已完成实现，真实 Wise ID、DeepSeek 与用户数据库暂不接入
> 建立日期：2026-09-02
> 产品重点：BTC、ETH、K 线、客观技术事实与人工行情判断

## 1. 产品定位

Wise Crypto 不再把产品目录和 Referral 作为子站主线。网站的核心任务是帮助用户围绕 BTC、ETH 完成：

```text
查看行情 → 阅读客观技术事实 → 查看 Wise 人工判断 → 使用风险工具 → 持续跟踪
```

公开功能继续提供可验证的市场数据、K 线和基础计算工具；VIP 功能承载多周期参考、人工关键位、主观行情策略、周期标记以及未来经过人工复核的 AI 回撤分析。

本项目不执行交易、不连接交易所账户，也不把任何自动结果包装成确定性收益或保证信号。

## 2. 用户等级

当前只定义两个等级：

```ts
type UserTier = "regular" | "vip";
```

- `regular`：普通权限。真实登录尚未接入时，所有公开访问默认使用此等级。
- `vip`：VIP 权限。未来只能由 Wise ID 的服务端身份结果授予。

不允许从 URL、`localStorage`、客户端状态、公开 Cookie 或任意请求字段直接声明 VIP。界面隐藏不是鉴权；未来 VIP 页面、API 和数据读取都必须在服务端再次检查权限。

## 3. 功能边界

下表描述目标权限，同时明确当前实现状态；“VIP 权限”不等于功能已经上线。

| 功能 | 普通用户 | VIP 目标权限 | 当前实现状态 |
|---|---:|---:|---|
| 市场总览、BTC / ETH 价格 | 可用 | 可用 | 已上线 |
| 基础 K 线、当前周期 EMA | 可用 | 可用 | 已上线 |
| 仓位、杠杆、DCA、风险回报工具 | 可用 | 可用 | 已上线 |
| 多周期客观参考 | 不可用 | 可用 | 已实现服务端四周期事实矩阵；等待 Wise ID 才向真实用户开放 |
| AI 回撤分析 | 不可用 | 可用，且必须经过人工复核 | 尚未接入 |
| 牛熊周期标记与周期对比 | 不可用 | 可用 | 方法与数据模型尚未确认 |
| Wise 人工关键位与主观策略 | 不可用 | 可用 | 已接入 schema、生命周期和权限隔离；当前生产内容为空 |

普通用户可以看到 VIP 能力名称和边界说明，但不能收到实际关键价位、方向、时间窗口、条件、策略正文或其他受限数据。

首页 `Market Status` 与 `Wise Take` 也属于主观判断，必须遵循相同 VIP 边界；
`Today in Crypto` 可以作为带逐条来源的公共事实简报继续开放。

## 4. VIP 内容类型

### 4.1 多周期客观参考

可以从经过验证的 Binance Spot K 线机械派生：

- `15m / 1h / 4h / 1d` 收盘价相对 EMA10、EMA20、EMA50、EMA200 的位置。
- 各周期均线的排序。
- 最近 20 根闭合 K 线的涨跌、最高、最低、收盘区间位置与距高点变化。
- 最新闭合成交量相对此前 20 根闭合 K 线平均量的比例。
- 样本数、算法版本，以及形成中 K 线是否已从计算中排除。

当前实现对每个周期读取最多 1,000 根 Binance Spot K 线，先校验时间连续性和
单一资产/周期口径，再统一排除形成中 K 线。四个周期独立保留 `source`、`scope`、
`updatedAt`、`retrievedAt`、`stale`、`cache` 和 `error`；单周期失败不影响其他周期。
页面顶部只汇总“多少个可用周期位于某条 EMA 上方”等机械事实，不给出多空评分。

这些输出只能描述事实，不能自动生成“做多”“做空”“开仓”或目标价。

### 4.2 Wise 人工行情策略

人工策略至少需要：

- 资产和方向倾向。
- 生效时间、有效期、审核时间和作者。
- 适用周期或时间窗口。
- 判断依据。
- 需要继续观察的条件。
- 确认条件和失效条件。
- 风险说明和来源。

内容过期后必须自动退出当前策略区；未发布、待审核和过期内容不得继续显示为当前判断。

真实 VIP 策略不得提交到 Git 仓库或打进公开可获取的静态资源。当前
`src/content/asset-editorial.ts` 只能保留空的 schema 占位；接入真实内容时必须改由
服务端在鉴权后读取受控私有 CMS / 数据库，并配置审计、撤回与用户隔离缓存。

### 4.3 牛熊周期标记

“牛市开始”“熊市开始”不是仅凭价格即可客观推导的统一事实，因此转接点必须来自明确的人工方法和版本：

- `methodologyVersion`
- `transitionAt`
- `transitionPrice`
- `regime: bull | bear`
- `rationale`
- `sourceIds`

历史周期涨幅和当前周期涨幅可以由已经核验的转接价格、阶段高点或当前价格机械计算，但必须同时展示起点、终点、时间和数据来源。

### 4.4 AI 回撤分析

未来接入 DeepSeek 时，模型输出默认只能进入草稿态。生产展示至少需要保留：

- 模型与版本。
- 输入数据的资产、周期、范围和截至时间。
- Prompt / 方法版本。
- 生成时间。
- 人工审核人、审核时间和有效期。
- 使用了哪些价格、均线、回撤或关键位证据。

模型调用只能发生在服务端。API Key、完整 Prompt、内部审核信息和未发布结果不得进入客户端。模型失败时显示 unavailable，不得用旧结论冒充当前结论。

## 5. 页面结构

BTC 与 ETH 页面优先顺序：

1. 价格与更新时间。
2. 大尺寸实时 K 线。
3. 当前周期 EMA 客观事实。
4. VIP 行情策略台。
5. 衍生品与市场背景。
6. 风险与仓位工具。

VIP 行情策略台包含：

- 多周期参考。
- 人工关键位。
- Wise 主观策略。
- 牛熊周期标记与历史对比。
- AI 回撤分析。

普通权限只渲染锁定说明和 Wise VIP 入口；真实 VIP 内容必须在服务端权限判断之后才进入 React 树和响应载荷。

## 7. 实施结果（2026-09-02）

- 默认访问固定为匿名 `regular`；仅服务端 Identity Adapter 的有效结果可以形成
  `vip` 权限对象，异常和非法值一律降级为普通权限。
- 功能权限集中在统一 capability map，没有 URL、查询参数、浏览器存储、公开 Cookie
  或环境变量 VIP 后门。
- BTC / ETH 的页面顺序调整为价格摘要、K 线与 EMA、VIP 行情策略台、衍生品、风险工具。
- 普通用户响应只含能力名称、规划状态和主站权益入口；即使服务端已有 active 人工
  策略，关键价格、方向、条件和正文也不会进入普通用户 HTML。
- 人工策略 schema 已要求倾向、作者、适用窗口、判断依据、确认/失效条件、风险说明、
  来源和有效期；当前仅以测试 fixture 验证，仓库不保存真实 VIP 策略。
- 通过服务端注入的已验证 VIP 权限测试 active、expired 与 unpublished 状态；生产
  默认仍为普通权限，不提供客户端切换按钮。
- 首页新增 BTC / ETH 策略台入口；产品入口退出 Header、Footer、首页、sitemap 和
  公开 `page_view`，历史路由固定 308 到主站 Crypto 福利页。
- 首页 `Market Status` 与 `Wise Take` 已在服务端对普通权限清空，`Today in Crypto`
  仍保留为可核验的公共事实内容；未来发布主观判断不会绕过 VIP 边界。
- 多周期服务在权限判断通过后才创建 Provider 请求；普通、未认证、身份异常路径均为
  零行情调用，并返回不含周期、来源、时间或数值的 `locked` 结果。
- 已验证 VIP 路径并行计算 15m / 1h / 4h / 1d，使用各自最后一根已闭合 K 线作为
  分析截至时间；形成中 K 线不参与 EMA、区间、回撤或量能事实。
- 多周期面板与人工策略使用独立 Suspense；任何周期的 error、stale、unavailable
  都独立展示，不会阻塞公开 K 线，也不会用零值或测试数据补齐。
- 每个可用周期提供可展开的审计口径，展示算法版本、闭合样本数、本次输入是否实际
  排除形成中 K 线，以及区间位置的 0%/100% 定义。
