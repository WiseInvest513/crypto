# Wise Crypto 实用性优化规格

> 状态：优化批次 A、BTC/ETH K 线专项、批次 B 的 B1–B4、VIP 行情研究基础、多周期客观参考与首页信息层级重设计已完成；B5 未开始，原批次 C 已取消
> 建立日期：2026-09-01  
> 基线版本：Wise Crypto V0（Phase 1–7 已完成）  
> 基线规范：`docs/product-specs/wise-crypto-v0.md`  
> 本地验收地址：`http://localhost:2222`

## 1. 文档目的

本文件定义 Wise Crypto V0 收口后的实用性优化方向、信息架构、低保真线框、实施批次与验收标准。

这不是新一轮大规模功能开发，也不自动开始所谓 Phase 8 或 V1。每个优化批次都必须单独获得确认，完成后运行全部质量检查并停止汇报。

本次优化的核心目标不是增加更多页面或视觉装饰，而是让用户更快完成四个真实任务：

1. 在 10 秒内知道当前市场发生了什么。
2. 在 30 秒内理解 BTC / ETH 的客观趋势与需要观察的条件。
3. 更快完成一次风险或仓位计算，并知道下一步可以检查什么。
4. 在行情事实、资产详情和风险工具之间形成清楚的使用路径。

## 2. 当前产品判断

### 2.1 已经成立的能力

- 市场数据保留来源、口径、数据截至时间、获取时间、缓存与状态。
- 缺失数据使用 `unavailable`，不会用零值或生产 Mock 填充。
- BTC / ETH 已具备价格、已闭合日线、MA20、MA50 和客观趋势事实。
- 四个计算器公式、输入验证、隐私边界和独立 URL 已完成。
- Phase 6 建立过来源核验、Pros / Cons 与 Referral 安全模型；该目录现已退出公开体验，
  代码仅作为未公开基础设施保留。
- Responsive、Accessibility、SEO、安全与生产构建基线已经完成。

这些能力构成 Wise Crypto 的可信度基础，优化时不得破坏。

### 2.2 当前主要问题

当前网站更接近“可信的数据资料站”，还没有完全形成“用户每天会打开的市场工作台”。

2026-09-01 在 `390 × 844` 移动端生产预览中的观察结果：

| 页面 | 观察结果 | 产品影响 |
|---|---|---|
| 首页 | “关键市场指标”约在页面 1016px，“工具与产品”约在 3294px | 用户首屏主要在阅读标题、资产明细和元数据，核心结论与操作入口出现过晚 |
| 首页 | Market Status、Today in Crypto、Wise Take 均为 unpublished | 差异化内容以大面积空状态出现，降低完成度感知 |
| 首页 | 审计时衍生品与资金流 0/7 可用；Funding / OI 超时，ETF / Liquidations 缺配置 | 严谨的不可用状态容易被普通用户感知为“网站坏了” |
| BTC / ETH | 价格和图表可用，但技术事实、衍生品、人工情景在长页面中彼此相距较远 | 用户需要多次滚动才能完成“看价格—看趋势—看风险背景” |
| 仓位工具 | 第一个输入项约在 635px，结果后没有明确下一步 | 工具能算，但任务完成路径较慢，计算器之间没有形成工作流 |
| 产品目录（历史） | 与 Wise Invest 主站 Crypto 福利页内容职责重叠 | 重复内容会增加过期、口径不一致和维护成本，因此已退出子站公开体验 |
| 全站 | Analytics facade 当前为 noop | 无法用真实使用数据验证页面排序和工具完成率 |

上述位置是本地审计证据，不是要求页面永久匹配某个像素值。优化验收以用户能否在首屏发现核心信息和操作为准。

## 3. 产品定位

Wise Crypto 的主要价值应当是：

> 可信、可解释、可操作的加密市场事实工作台。

它不是交易终端、自动投顾或指标百科。所有新增展示应优先回答：

- 现在发生了什么？
- 与前一个可比较周期相比有什么变化？
- 哪些客观条件值得继续观察？
- 用户接下来可以完成哪一个具体任务？
- 这项数据截至什么时候；需要核验时，完整来源链是否仍可追溯？

## 4. 不可回归的产品边界

### 4.1 数据真实性

- 不新增生产 Mock，不用静态数字冒充实时数据。
- 缺少可靠来源时继续返回 `unavailable`，绝不展示为 `0`。
- 单交易所数据继续明确标注交易所、合约、计价单位和周期。
- 不静默混合不同 Provider 的历史序列或不同方法的指数。
- 所有派生事实必须保留底层输入的 source、scope、asOf、retrievedAt、stale 和 cache 信息。
- UI 继续只消费服务端标准化领域服务，不直接调用第三方 API。

### 4.2 内容与判断

- 不自动生成 Wise Take、Market Status、Support、Resistance 或 Wise Scenario。
- 自动派生内容只能陈述可验证的市场事实，不能出现“应买入”“看多”“机会”“安全区”等建议性措辞。
- 前一日高低、20 日区间和均线位置只能称为“观察条件”或“参考区间”，不能冒充人工支撑阻力。
- 人工内容必须继续包含来源、审核时间、生效时间、有效期和失效条件。

### 4.3 隐私与商业边界

- 不把余额、入场价、止损价、目标价、计算结果或用户标识发送到 Analytics。
- 不把用户金融输入写入分享 URL。
- 历史 Referral 模型继续使用服务端配置和精确 hostname 白名单，但当前没有公开调用方。
- 若未来重新启用产品能力，不做排行榜、分数或未经证实的“最佳”标签，也不伪造
  费用、资格、地区可用性、优惠或 Wise Benefit。

### 4.4 工程边界

- Server Components 仍为默认选择。
- Client Components 只负责真实浏览器交互，例如筛选、比较、表单和展开状态。
- 公共页面继续独立于未来 Wise ID/session 状态。
- 构建流程不能依赖实时 API 成功。
- 所有本地开发和生产预览继续使用端口 `2222`。

### 4.5 路由、SEO 与 Analytics 兼容

- 当前公开路由继续可访问；历史产品分享链接以固定永久重定向兼容。
- 全局导航包含市场总览、BTC、ETH、工具。
- 默认语言继续为简体中文，根文档继续使用 `zh-CN`。
- Production canonical 继续固定为 `https://crypto.wise-invest.org`，非生产环境继续 `noindex`。
- 公开 `page_view` 只允许当前市场与工具路由；`tool_open`、`tool_complete` 的名称
  和隐私边界不得回归。历史产品事件 facade 保留但不再触发。
- Analytics 失败不得阻断导航、计算或外链；未确定隐私政策前继续允许 noop adapter。

## 5. 全局信息架构

### 5.1 顶层导航保持稳定

```text
市场总览  /  BTC  /  ETH  /  工具
```

本轮不增加新的顶层栏目。优化通过重新排序现有信息、建立跨页面入口和减少噪声完成。

### 5.2 核心用户路径

```text
首页市场事实
  → BTC / ETH 资产详情
    → 仓位 / 风险回报 / 杠杆 / DCA 工具
      → 下一项中性风险检查
```

页面之间只传递非敏感的资产 slug 或工具 slug。金融输入和计算结果不得跨页面自动
传递或持久化。

## 6. 优化批次

### 6.1 优化批次 A：首屏价值与数据降噪（P0）

这是建议首先实施的批次。它不增加新的第三方数据源，不修改计算公式，不创建登录或数据库。

### A1. 首页重排

首页默认顺序调整为：

1. 页面价值主张、数据时间与 BTC / ETH 核心行情。
2. “市场现在”客观事实摘要。
3. VIP 人工策略入口。
4. 仅在 active 时显示的人工内容。
5. 关键市场脉搏。
6. 四个风险工具入口。
7. 默认收起的衍生品、资金流和完整数据覆盖详情。

首页首屏必须优先显示有效数据和下一步操作，不能优先显示 unpublished 或 unavailable 大卡片。

### A2. “市场现在”客观事实摘要

允许使用现有经过验证的报价和已闭合日线，最多生成 3 条事实句子：

- BTC / ETH 的 24 小时与 7 日变化是否同向或背离。
- 最新已闭合日线收盘价相对 MA20 / MA50 的位置。
- MA20 与 MA50 的相对位置。
- 最新收盘价位于近 20 个已闭合交易日区间的上部、中部或下部。
- 最新已闭合日线收盘价距离 MA20 / MA50 的百分比。

生成规则：

- 只能使用完整、经过验证且时间关系明确的输入。
- 输入 stale 时，事实句必须继承 stale 状态并显示数据截至时间。
- 任一必需输入缺失时，省略对应句子，不生成占位判断。
- 24h / 7d 变化只能在同一报价 Provider 的同一 quote 中比较。
- MA、区间和距离只使用同一 Binance Spot USDT 已闭合日线序列，不与聚合 USD headline 静默混算。
- 日线事实使用独立 Suspense 边界流式显示；K 线慢或失败时不能阻塞 BTC / ETH headline 和 quote-only 事实。
- 句子必须使用描述性措辞，例如“BTC 最新已闭合日线位于 MA20 上方”。
- 不使用“强势、弱势、超买、抄底、突破有效、目标价”等判断性词语。

### A3. 客观观察条件

首页和资产页可以显示下列机械计算值：

- 前一根已闭合日线最高价与最低价。
- 近 20 根已闭合日线最高价与最低价。
- MA20、MA50。
- 最新已闭合日线重新进入或离开上述区间时的事实条件。

模块标题使用“接下来观察”或“客观观察条件”。必须同时说明：

> 这些数值来自历史价格的机械计算，不是人工支撑、阻力或投资建议。

### A4. 人工内容空状态

- `active`：正常显示完整内容、审核和有效期；来源继续在服务端配置中强制校验，
  首页摘要不逐条重复来源链接。
- `expired`：从首页核心信息流移除，可在页面底部以紧凑状态说明“内容已过期，等待更新”。
- `scheduled`：公开页面不占据核心版面。
- `unpublished`：公开页面不渲染大面积空卡片。
- 不得自动补写默认 Market Status、Today in Crypto 或 Wise Take。

### A5. 数据状态降噪

- 有效指标继续正常显示。
- stale 指标继续显示数值，并突出“截至时间”和 stale 状态。
- error / unavailable 指标不再逐项占据主信息层的大卡片。
- 同一区域完全没有有效值时，显示一条紧凑的“数据覆盖状态”，并提供可展开详情。
- 展开详情保留每项 reason、source、scope、retrievedAt、cache 和最后成功时间（如存在）。
- ETF Flow 在可靠商业来源接入前不进入首页主内容层。

### A6. 元数据层级

默认展示：

```text
来源 · 数据截至时间 · fresh/stale
```

折叠在“查看数据口径”中：

```text
完整 scope · retrievedAt · cache hit/miss · revalidate · fallback · error reason
```

所有信息仍然存在并可访问，只调整默认视觉权重，不删除数据谱系。

### A7. 非核心请求预算

- BTC / ETH headline 和首页核心行情继续独立于衍生品请求。
- 非核心 Funding / OI 等页面请求建议使用 2–3 秒预算和单次页面级尝试。
- 失败后使用现有 circuit breaker、backoff 和 last-known-good 语义。
- 不能为了更快而展示过期到超过 hard-expiry 的数据。
- 具体超时值在实现前结合 Provider 政策和现有测试确定，并写入常量而不是散落在组件中。

### A8. 第一批不改动

- 不接入新的付费 API。
- 不修改四个工具的公式。
- 不增加产品比较页。
- 不接入 Analytics vendor。
- 不建立 CMS、数据库、提醒或账户体系。
- 不自动发布任何人工观点。

### 6.2 优化批次 B：资产到工具的任务闭环（P1）

本批次必须在批次 A 完成并汇报后单独确认。

### B1. BTC / ETH 详情页

- 顶部增加紧凑资产摘要：价格、24h、7d、MA20、MA50、客观趋势、source + asOf。
- 增加“价格 / 趋势 / 衍生品 / 人工情景”页内锚点。
- 无有效衍生品时只显示数据覆盖摘要，不展示连续空卡片。
- 人工关键位和 Scenario 只有 active 时进入主信息流。

### B2. 资产到工具

- 增加“计算仓位”“检查风险回报”“估算保证金”“查看 DCA”入口。
- 入口可以携带 `asset=btc|eth`，不能携带用户金融输入或计算结果。
- 如工具需要当前参考价，应由工具页通过标准化服务重新读取，并要求用户主动点击“使用当前参考价”。
- 参考价必须展示来源和 asOf，且用户可以修改。

### B3. 工具之间的下一步

- 仓位结果 → 检查风险回报 / 保证金。
- 风险回报结果 → 检查仓位风险。
- 杠杆结果 → 检查仓位风险与风险回报。
- DCA 结果 → 查看同资产长期区间，不引导短线交易。
- 下一步链接不得自动传递金融输入。

### B4. 工具首屏

- 页面标题和边界说明压缩为紧凑头部。
- 表单应在移动端第一屏开始出现。
- “复制工具链接”降为次要操作。
- 公式、完整解释和免责声明继续保留在表单之后或可展开区域。

### B5. DCA 对照基线

使用相同历史数据和相同总投入，增加：

- 按计划 DCA。
- 在第一个有效日一次性投入。
- 保留 USDT 现金的机械基线。

只展示结果差额，不使用“胜出、更优、推荐”等措辞。

### 6.3 原优化批次 C：已取消

产品筛选、比较、详情重排与 Referral 转化不再属于 Wise Crypto 子站范围。产品、
邀请码和权益详情统一由 Wise Invest 主站的 Crypto 福利页维护。原有产品代码与
安全校验保留但不公开；如未来恢复，必须重新立项并重新核验全部事实。

## 8. 批次 A 验收标准

### 8.1 实用性

- 在 `390 × 844` 的初始视口内可以看到 BTC、ETH、24h / 7d 变化、数据截至时间和至少一个明确操作入口。
- “市场现在”和关键市场脉搏应在页面前 1100px 内开始出现，不得被空编辑卡或完整元数据推到其后。
- 首页首个屏幕不得由 unpublished、error 或 unavailable 大卡片主导。
- “市场现在”最多展示 3 条客观事实；无有效输入时整个句子省略。
- 工具入口必须早于完整衍生品失败详情。
- 页面仍能在核心数据全部 unavailable 时清楚解释状态并提供工具和静态导航。

### 8.2 数据与内容
